# OnPoint — Website Architecture ↔ Systems Book Sync Map (v2026-02-17r3)

**Purpose:** Keep the **website**, **Notion**, and **Systems Book (Word/PDF)** synchronized as *one system*—with a single source of truth, clear IDs, and registry-driven version locks.

**Scope in this revision:** adds **Public Site + Data Room/CIM journey pages**, defines **canonical coding**, and includes a **Notion “Sync Tracker” template** plus **publishing cadence**.

---

## 1) Canonical Coding Standard (works in Website, Notion, Word)

### 1.1 IDs (never change once issued)
Use IDs everywhere: headings, Notion records, website CMS items, filenames, and registries.

- **Systems Book sections:** `SB-##` (ex: `SB-04`)
- **Appendix modules:** `APPX-[A-Z]` (ex: `APPX-B`)
- **Website pages:**
  - Internal/ops pages: `WP-##` (ex: `WP-04`)
  - Public pages: `WP-PUB-##` (ex: `WP-PUB-02`)
  - Data Room/CIM pages: `WP-DR-##` (ex: `WP-DR-04`)
- **Reusable copy blocks (optional but recommended):** `CB-###` (ex: `CB-014`)
- **Assets:** `ASSET-[TYPE]-###` (ex: `ASSET-DIAGRAM-007`)

### 1.2 Slugs (website)
- Lowercase, hyphenated, no dates in slugs.
- Always include the section code if it’s a book-derived page:
  - `/systems-book/sb-04-master-control`
  - `/systems-book/sb-10-finance-controls-system`

### 1.3 Word heading styles (book)
- **Heading 1:** Chapter / SB section title (ex: “SB-04 — Master Control Layer”)
- **Heading 2:** Sub-sections within a chapter
- **Heading 3:** Procedures / checklists / steps
- **Body:** Narrative content
- **Caption:** Figures / diagrams

> Rule: The **SB/WP code is always the first token** in the heading line so it survives copy/paste into Notion and the website CMS.

## 2) Canonical Source-of-Truth Rules (the “one system” contract)

### 2.1 Source hierarchy (default)
1. **Systems Book (Master DOCX)** = canonical for “how we operate”
2. **Notion** = canonical for “what’s current + operational status”
3. **Website** = canonical for “what we publish externally”

### 2.2 Allowed sync patterns
- **1-way (Book→Notion):** procedures, policies, standards
- **2-way (Web↔Notion):** marketing pages that evolve fast (Authority OS overview, solutions)
- **1-way (CIM→Web):** data room deliverables (Teaser, NDA email content, CIM, Appendix Pack)

### 2.3 Version locks
- Every outward-facing artifact is locked to a version string:
  - Example: `v2026-02-17r3`
- Any external update requires:
  1) Registry line item update  
  2) Version bump  
  3) Distribution log entry

## 4) Notion “Sync Tracker” — CIM + Website + Book

Create a database called: **`OPS — Sync Tracker`**

### Properties (recommended)
- **Title** (text): Human title (ex: “SB-04 — Master Control Layer”)
- **Canonical ID** (text): `SB-04`, `WP-DR-04`, etc.
- **Type** (select): BookSection / WebsiteOnly / CopyBlock / Asset / CIMDeliverable
- **Source of Truth** (select): Book / Notion / Website / CIM
- **Website Slug** (text)
- **Word Style** (select): H1 / H2 / H3 / Body
- **Status** (select): Planned / Draft / Active / Deprecated
- **Owner** (person/select)
- **Version Lock** (text): `v2026-02-17r3`
- **Last Sync Date** (date)
- **Next Review** (date)
- **Change Notes** (text)
- **Links** (url): add links to OneDrive file + live page

### Views
- **By Status**
- **Book Chapters**
- **Website Pages**
- **Data Room / CIM**
- **Needs Review (Next Review ≤ Today)**

## 5) Publishing Cadence (so drift doesn’t happen)

### Weekly (Ops hygiene)
- Review: **“Needs Review”** view
- Update: owners fix content in the canonical source
- Sync: update linked surfaces (Notion ↔ Web) as required
- Log: registry bump if anything externally visible changed

### Monthly (external polish)
- Refresh public pages (WP-PUB-*)
- Refresh Data Room pages (WP-DR-*) only if you’re actively in market / outreach

### Quarterly (system integrity)
- Freeze “Systems Book” PDF export
- Run a link check: website → Notion → files
- Audit: registry completeness + distribution log

---

## 6) Folder + Registry Model (what to keep in OneDrive)

### 6.1 Folder principle
**One canonical master file per deliverable**, then exports.

- `MASTER/` = editable source (DOCX, PPTX)
- `EXPORT/` = PDF and “distribution-ready” files
- `REGISTRY/` = version registry + distribution log

### 6.2 Recommended top-level structure (excerpt)
- `02 SYSTEMS BOOK/00 MASTER/`
- `03 WEBSITE/01 COPY BLOCKS/`
- `04 CIM PROGRAM/`
  - `01 TEASER/`
  - `02 NDA/`
  - `03 CIM/`
  - `04 BUYER DECK/`
  - `05 APPENDIX PACK/`
  - `REGISTRY/`
