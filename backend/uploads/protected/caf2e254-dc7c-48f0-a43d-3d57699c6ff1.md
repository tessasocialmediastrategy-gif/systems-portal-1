# Website Architecture ↔ Book Sync Map (v2026-02-17r1)

## Purpose
A single crosswalk that keeps Website Architecture pages, Notion operating pages, and the Systems Book chapters synchronized using one shared **Canonical ID (CID)**.

## Canonical ID (CID) Rules
- **CID is universal**: the same string must appear in **Notion**, **Word**, and **Website**.
- **Format**: `SB-##-##` or `SB-##-##-##` (matching the Systems Book section codes).
- **No renumbering** after external publication. If structure changes, add a new CID and mark the old CID as `DEPRECATED` (keep it for traceability).

### Where the CID lives
**Website (front matter / page metadata)**
```yaml
cid: SB-04-02-01
version: v2026-02-17r1
lock: locked | draft
source_of_truth: notion
```

**Notion (properties)**
- `CID` (text, required)
- `Status` (Draft / Review / Locked)
- `Owner` (person)
- `Last Synced` (date)
- `Source of Truth` (select: Notion / Book / Website / Registry)

**Word (heading format)**
- Prefix every Heading 1/2 with the CID (as already used in the book).
- Keep the CID unchanged even if the title wording changes.

## Sync Workflow (Version-Locked)
1. **Draft/Revise in Notion** (operating system).
2. **Commit to Book** (Word master) with CID preserved; increment `version` in header/footer or document control.
3. **Publish to Website** by rendering the matching CID pages; set `lock: locked` when released.
4. **Log releases** in the registry (version, date, owner, diff summary).

- Every page/chapter has exactly **one** CID.
- Website pages include **cid + version + lock** fields.
- Notion row contains **CID + Status + Owner + Last Synced**.
- Any externally shared artifact is marked **LOCKED** and matches the registry version.
